# pachinko-simulator-lycoris 設計仕様書

## 背景

パチンコシミュレーター「eリコリス・リコイル」を新規作成する。
既存プロジェクト `pachinko-simulator-ghoul` と同じアーキテクチャ・UIシェルを踏襲し、
確率・ゲーム性はLycoris Recoilのスペックに差し替える。
画像素材・Supabaseランキング機能は今回のスコープ外（後日追加検討）。
配色は白ベースとする。

## アーキテクチャ

- フォルダ: `C:\Users\ab_99\pachinko-simulator-lycoris`
- `index.html` / `script.js` / `style.css` の3分割構成（`pachinko-simulator-ghoul` と同じ）
- `logic.js`: 純粋な確率・状態遷移ロジックのみ（DOM非依存）、Node標準の`node:test`でユニットテスト
- 画像素材なし（テキスト・CSSのみ）。Supabaseランキングは実装しない
- UIシェルは `pachinko-simulator-ghoul` を流用し、文言・配色をLycoris Recoil向け・白ベースに差し替える
  - ヘッダー（持ち球／投資／収支／回転数）
  - 1000円あたりの回転数プルダウン（14/16/18/20回転、デフォルト16）
  - 「1万円分回す」一括回転ボタン（選択レートに応じた「約◯回転分」表示）
  - 退店・リザルト画面
  - 営業時間終了アラート（ghoul版同様2000回転を踏襲。値の変更要望があれば別途対応）
- 本作には「先バレ」演出に相当する仕組みが存在しないため、ghoul版の先バレ確率選択（40%/90%）UIは搭載しない

## LT中ロジック（ST方式）

- LT名称：「SPECIAL LycoReco RUSH HYPER DELUXE」
- ST（電サポ）回数：132回転。**当選するたびに132回にフルリセット**。132回転以内に当選できなければLT終了→通常時へ（ST回転数はリセットされた状態で戻る＝次回突入時は132からスタート）
- LT中の当選確率：1/97.1
- 内部モードA/Bが存在（**画面表示用データには一切含めない、純粋な内部変数として保持**）

### 初回LT突入時のモード決定

- 通常時の大当たりからLT突入したタイミングで、70%モードA／30%モードBを抽選（**毎回独立試行、前回セッションのモードは持ち越さない**）

### モードA当選時

- 出玉：一律750個（実質700個獲得）
- 次モード抽選：50%モードB／50%モードA継続

### モードB当選時

- 出玉：一律3000個（実質2800個獲得、基本分）
- 基本分の後、**ST消化とは独立した上乗せループ**を実行：
  - 50%で成功 → 追加で3000個（実質2800個）を上乗せし、ループを継続（再度50%抽選）
  - 50%で失敗 → 上乗せループ終了（**LTそのものは終了しない**。この一連の当選イベントが終わるだけ）
  - 上乗せループが何連鎖しても、ループが終わった時点のみ以降の処理（次モード抽選・ST132リセット・カットイン表示）に進む
- 上乗せループ終了後、次モード抽選：93%モードA／7%モードB継続

### 当選イベント共通の後処理（モードA・モードB問わず）

1. ST残り回数を132にフルリセット
2. 次モード（またはモードB上乗せループ終了後の次モード）を確定
3. 確定した次モードに応じて、下記の色抽選テーブルで表示色を1回だけ抽選
4. 「ラッシュ開始！」カットインを表示（下記「LT名カットイン表記」参照）
5. LT継続（ST132スタートの電サポ画面へ）

初回LT突入時（通常時の大当たり後、70%/30%でモード確定した直後）も、同様にカットインを1回表示してからLT開始する。

### 色抽選テーブル（モード→色）

| 色 | モードA時の出現率 | モードB時の出現率 |
|---|---|---|
| 虹 | 0% | 15% |
| 赤 | 3% | 40% |
| 緑 | 19.4% | 31.5% |
| 青 | 77.6% | 13.5% |

参考：初回LT突入時（A70%/B30%基準）で見た場合の色ごとの「モードB期待度」はおおよそ虹100%／赤85%／緑41%／青7%。

### LT名カットイン表記

- 小さく「ラッシュ開始！」を表示。この文字色を、直前に確定した色抽選テーブルの結果（虹/赤/緑/青）にする
- その下に大きく「SPECIAL LycoReco RUSH HYPER DELUXE」を表示。この文字は**常に金色固定**（モード色ではない）
- モードA/Bという内部状態そのものは一切画面に表示しない。プレイヤーが得られる情報は上記カットインの色のみ

## モード非表示の実装制約（重要）

- 内部モードA/Bは、ゲーム状態オブジェクト内の完全に内部用のプロパティとして保持する
- 画面描画（レンダリング）関数がこのプロパティを直接参照して表示することは一切あってはならない
- 色抽選の結果（色そのもの）だけが画面表示用データとして扱われる

## 実装要件

- `logic.js`：通常時スピン処理・大当たり振り分け抽選、LT中のST消化（132リセット）、モードA/B内部状態遷移、モードB上乗せループ、色抽選ロジックを、DOM非依存の純粋関数として実装し、Node標準`node:test`でユニットテスト
- `script.js`：ゲーム状態管理・画面描画。ghoul版のUIシェル（ヘッダー・スピンレート選択・一括回転ボタン・退店/リザルト画面）を踏襲しつつ、Lycoris Recoil向けの画面（大当たり振り分け結果、LT中電サポ画面、モードB上乗せ結果、LT名カットイン、LTリザルト画面）を新規実装
- 実戦データ表示：出玉カウンター、大当たり履歴、LT突入率・LT継続率などをリアルタイム表示（ghoul版の「通算RUSH成績」相当の仕組みを踏襲）
- Supabaseランキング機能は実装しない（将来のスコープ）
- UI/演出は簡易でよく、ロジックの正確性を最優先する

## スコープ外（今回は対象外）

- 画像・カットイン画像などのビジュアル素材
- Supabaseによるランキング機能
- 先バレ演出に相当する仕組み（本スペックには存在しない）
